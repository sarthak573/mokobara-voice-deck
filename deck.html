Core Thesis
The bot harvests intent, it doesn't sell — and ~60% of dials never reach a person, so Mokobara pays for calls that go nowhere.
Fixing "who we reach" + "how we close" is the upside. This is a cost-efficiency story, not only a conversion story.
Measurement Caveat
Attribution is last-touch / 5-day window — this likely over-credits the bot. Real incrementality may be lower. Numbers are as-is from the dataset.
ROI Framing
  • Bolna charges Bitespeed per call → Bitespeed charges Mokobara
  • Every silent (196) + voicemail (42) dial = spend with zero return
  • Fixing reach = direct ROI improvement, not a speculative bet

LEAK 1a · ROI DRAIN 196 calls · 49% P0 Fix
Silent calls — 196 (49%) of dials
Bolna answers, nobody talks. Client pays. Zero return.
Root Causes
  • Cold open — Bot speaks into silence; human doesn't know who's calling → hangs up
  • AMD failure — Answering Machine Detection misses IVRs / voicemail-as-pickup
  • Honest caveat: some silent calls are undetected machines — AMD fixes this too
Solutions (P0)
  • Redesign cold open: "Hi, I'm calling about your [brand] bag in your cart — do you have 30 seconds?"
  • Enable / tune Bolna AMD; retry on machine detection with SMS fallback
  • Add silence-detect → retry logic: 3 s of silence → escalate / disconnect
Sample 1 — No intro: "am I speaking with Saif?" → silence (15s)
Sample 2 — "क्या मैं Rahul से बात कर रही हूँ?" — no brand intro → silence (15s)
Sample 3 — No intro: "am I speaking with Abilasha?" → silence (7s)

ROI Impact
196 wasted calls × per-call cost = direct recoverable spend. AMD turns machine-pickups into retries instead of paid dead air.
LEAK 1b · ROI DRAIN 42 calls · 10% P0 Fix
Voicemail dials — 42 (10%) of answered calls
Bot pitches to a machine. No human. Pure cost.
Root Causes
  • AMD not detecting the machine before the bot starts its script
  • Bot delivers the full pitch to a recording — the whole call (and spend) is wasted
  • No fallback when a machine is detected — the attempt is simply burned
Solutions (P0)
  • AMD → detect the machine and disconnect immediately (never pitch a recording)
  • Send the checkout link via WhatsApp (the channel the bot already uses) instead of leaving a voicemail
  • Re-queue the number for a retry in a human-answer window
Sample 1 — Voicemail greeting: "record your name and reason…" (6s)
Sample 2 — Carrier notice: "…recording this call for the person you're trying to reach" (17s)
Sample 3 — Undetected machine (AMD miss): "am I speaking with Kusuma?" → no human (7s)
ROI angle: Silent (196) + Voicemail (42) = 238 calls with zero conversion potential. This is ~59.5% of all answered calls. Fixing AMD alone recovers this spend.

LEAK 2 · CLOSE GAP 38–49 calls P0 Fix
The bot doesn't close — no commitment gate
Link sent. Customer vanishes. Conversion = 0.
Root Causes
  • Bot sends link without asking "should I send it?" — no micro-commitment
  • Close line is passive: "Let me know if you need anything"
  • No urgency, no follow-through if link unopened
  • Engaged buyers lose momentum after call ends
Solutions (P0)
  • Add commitment gate: "Would you like me to send the checkout link now?"
  • Replace passive close with active: "I'm sending it now — you'll get it in seconds."
  • If link sent but unopened after 10 min → trigger a WhatsApp nudge
Sample 1 — Interested, then link dumped, no commitment (40s)
Sample 2 — "I need more time" → bot backs off & ends, no close (47s)
Sample 3 — Customer unsure on size → bot sends link instead of resolving (2m44s)

LEAK 3 · CAPABILITY Engaged Buyers Lost P1 Fix
Capability gaps lose engaged, ready-to-buy customers
Cart-link failures · language lock · hallucinated product details
Root Causes
  • Can't change the cart — bot says "I can't change it" instead of sending an updated cart link
  • Unprompted language switching — bot flip-flops Hindi/English without the customer asking, creating friction
  • Hallucination / grounding — bot gives contradictory product info (e.g. self-contradicts on colour)
Solutions (P1)
  • Give the bot a tool to generate & send an updated cart/checkout link on request
  • Detect the customer's language from their speech and lock to it; switch only to mirror them
  • Ground product answers (colour/variant/availability) in the catalog; no free-form claims
Sample — One 554s call, 5 objections: cart-change refused, language flip-flop, colour self-contradiction

LEAK 4 · QUALITY ~23 calls affected P1 Fix
Quality friction: talkover, repetition, handoff loops
Buyers hang up out of frustration, not disinterest.
  • Talkover — bot speaks over the customer mid-sentence (VAD not tuned)
  • Repetition — bot re-says the same line; customer disengages
  • Handoff loop — customer asks for a person → bot loops the same line instead of escalating
Solutions (P1)
  • Enable barge-in / tune VAD so the customer can interrupt
  • Real escalation path: when a human is requested → hand off / log a ticket, don't loop
  • Add in-call memory so the bot doesn't repeat itself

Methodology
How I got here — rigor, not vibes.
Step 1 — Listen
Listened to representative samples across all outcome categories. Built intuition before building code.
Step 2 — Taxonomy
Defined a call outcome taxonomy: silent, voicemail, conversation (closed / unclosed / link sent), and leak categories.
Step 3 — Analyzer
Built a reusable transcript-analysis pipeline (multi-provider free LLMs — Groq/Gemini — with batching, caching + structured evals). Processes all 400 calls with consistent labels.
Step 4 — Validation
10-agent cross-check on ambiguous cases + golden-label evals. Self-scoring vs manual review. Caught and corrected edge cases.
Every finding in this deck is traceable to a real call recording. The analyzer output is auditable — no black-box conclusions.
Validation principle · all 400 calls labeled + linked
The same pipeline is reusable across any Bolna/AI-voice client. This analysis took days, not weeks, because of the tooling built alongside it.

Approach & metrics
  • Independent golden set (85 calls) — labeled from structural signals + a 10-model cross-check + attributed orders, never from the analyzer itself (no circular scoring).
  • Per-field metrics — accuracy + confusion matrix (single-label); precision/recall/F1 (multi-label flags); LLM-as-judge (free-text coaching).
  • Pass bar — a brand ships only when drop-reason accuracy ≥ 85%.
  • Regression — evals re-run on every prompt/model change; reusable + cost-efficient across 5000+ brands.
